Reading guide, architectural contracts, sources and design notes

Use this view to introduce the product. The Solution Engineer owns an independent Windows installation, database and service connections. The six workspace cards summarize capabilities; they are neither separate deployable services nor the application's exact navigation groups. The component reference retains the individual routed and shared surfaces.

How to read the workflows

  • Refresh context: the saved active TPID roster bounds CRM and M365 collection. Ingested evidence is normalized, redacted, linked and persisted. Account archiving removes active membership without deleting local history.
  • Investigate: application code gathers bounded local grounding or performs permitted live reads. AI interprets and synthesizes it. Source access, citations, gaps and provider failures are visible rather than silently substituted.
  • Act: reviewable outputs can become Tasks, workloads or saved research. User-directed CRM mutations and Outlook reply-all draft creation are distinct application actions, not research-tool powers. The application does not send email.

Important boundaries

  • Local-first means local ownership, not that every computation stays on the device. Bounded, feature-specific grounding is sent to a remote model when the user invokes AI.
  • The Electron main process owns privileged integration, model, persistence and execution work. Agent specifications are local code, not autonomous hosted services. The runtime view separates renderers, preloads, main, subprocesses and local storage.
  • All model work, including desktop-launched Python AI, enters the shared model-request scheduler. Connected Copilot is an explicit provider choice; its failure never switches to Foundry. Foundry requires Copilot to be disconnected, complete configuration and feature eligibility.
  • Work Agent, Work Outputs/research, influence analysis and ingestion AI are Copilot-only. Public research sends generic, scrubbed queries; it is not an identity or data-source replacement for enterprise research.
  • Not all remote results go into SQLite. ACR has durable row caches; Foundry Deep-Dives usage has a 15-minute identity-scoped memory cache. Directory, documents and original-email research can be read live.
  • The lines are selected request/data relationships; responses are implicit. Source-category cards summarize independent integrations and do not introduce an API gateway, event bus or cloud application backend.
